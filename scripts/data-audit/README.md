# Data audit scripts (Wikidata-based)

Used to audit and expand the Link-Up player database and Side Netting prompts (Oct 2026).
Python 3, no dependencies. They talk to the Wikidata Action API (not the SPARQL service),
throttled to ~1 request / 3 s because anonymous traffic is rate-limited.

- `club_map.json`   game club slug -> Wikidata club id (518 of 686 clubs mapped, 98% of club appearances)
- `wdapi.py`        cached Wikidata API client (search, haswbstatement search, entities)
- `nations.py`      national-team label -> canonical nation (filters youth/olympic/regional teams)
- `rebuild_linkup.py`  fixes clubs/nations/namesakes of Wikidata-linked Link-Up players
- `sn_manual.py`, `sn_2026.py`, `apply_sn.py`  hand-audited Side Netting corrections
- `net_jobs.py`     fetches answer pools for club-based prompts + Link-Up expansion candidates
- `apply_generated.py` applies those (fame-tiered answers; new players need >=25 sitelinks, born >=1950, >=2 game clubs)

The scripts expect their cache files (wd_players.json, prompts.json, sn_generated.json,
expansion_candidates.json, cache/) next to them; they are regenerated by the fetch scripts.

Oct 2026, second pass:
- `sn_batch2.py`    Side Netting batch 2 (100 prompts, 30 tagged `broad`). `plan` -> `sparql` (one query per club,
                    the Action API was 429-limiting) -> `apply --write`. Answers need 3+ sitelinks.
- `rb_verify.py`    Record Books consistency checks (`checks`) + Wikipedia records-page probe (`wiki`).
- `rb_infobox.py`   fetches every listed player's English Wikipedia infobox (cache/wiki_infobox.json).
- `rb_rebuild.py`   rebuilds Record Books as LEAGUE goals from those infoboxes; drops players with no senior spell
                    at the club; merges duplicates; removes assists (no reliable source).
- `rb_names.py`     names each entry after the page its count came from (the old data had wrong aliases).
  `recordBooksData.after_rebuild.json` is the output of rb_rebuild.py, before rb_names.py.
